# W5 — Boss framework and Warden
Status: done
Gate: `bun run verify` → exit 0 (includes boss fairness + runtime suites)

## Built
- `src/sim/boss.ts`: generic data-driven boss runtime with five-pattern cycle, telegraph/active/vulnerable phases, movement modes, projectile volleys, phase events, module exposure/destruction events, routed damage to exposed modules, core armour, and defeat reporting.
- `src/data/boss.warden.json`: authored Generation 1 arc with five patterns, per-pattern projectile damage, three exposed modules, and phase thresholds.
- `src/data/boss.warden.gen2.json`: Generation 2 arc expressed entirely through data (higher HP, faster/denser patterns).
- `src/sim/world.ts`: integrated runtime into the world loop, hard runs select Gen2, runtime events map to sim events, and projectile impacts use module-aware damage routing.
- `src/main.ts`: telegraph ring, module weak-point rendering/health, exposure labels, and generation-aware boss HUD.
- `tests/sim/boss-runtime-analysis.spec.ts`: runtime data validation, five-pattern cycle, exposure open/close, module routing, core armour, defeat, Gen2 hard-run integration, and volley emission.
- `tests/sim/boss.spec.ts`, `tests/sim/boss-arc-validator.spec.ts`: fairness/data invariants.

## Contracts exposed
- `createBossRuntime(spec, options)` — creates validated runtime state from boss JSON.
- `stepBossRuntime(state, spec, input)` — deterministic pattern/exposure/projectile state machine.
- `damageBossRuntime(state, amount, impactX, impactY)` — module-aware damage routing and core armour result.
- `bossGenerationForRun(difficulty, wave)` — data-driven generation selection.
- `validateBossArc(spec)` — deterministic fairness validation.

## Deviations from plan
- Runtime lives in `src/sim/boss.ts` rather than a renderer-coupled boss controller; all visual feedback is event/HUD driven so the sim stays pure.
